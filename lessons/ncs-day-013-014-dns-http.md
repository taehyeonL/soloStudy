## 이론 목차

1. 문서별 목적과 독자
   1.1 보고서의 현황·근거·제안 구분
   1.2 규정의 적용 대상·조건·예외 확인
   1.3 메일의 요청 행동·담당자·기한 확인
2. 여러 문서 대조
   2.1 공통 사실과 문서별 차이 표시
   2.2 근거에 없는 결론을 덧붙이지 않기

### NCS Day 14 — 의사소통 미니평가
1. 문서 근거 찾기와 목적 구분
2. 조건·기한·예외 통합
3. 오답 선택지의 범위 확대·누락 점검

### 전산 전공 + 정보보안기사 필기 공통 — DNS와 HTTP/HTTPS
1. DNS
   1.1 도메인 이름을 IP 주소로 해석하는 계층적 이름 서비스
   1.2 캐시와 응답의 의미
2. HTTP
   2.1 클라이언트 요청·서버 응답 구조
   2.2 상태 코드의 큰 분류: 2xx 성공, 3xx 재지정, 4xx 요청 측 문제, 5xx 서버 측 문제
3. HTTPS와 보안 한계
   3.1 HTTPS는 TLS를 사용하여 통신 경로의 기밀성·무결성을 보호하고 서버 인증을 수행
   3.2 HTTPS 자체가 애플리케이션 권한 검사나 취약점 제거를 보장하지 않음

표준 근거: [RFC 1034 DNS concepts](https://www.rfc-editor.org/rfc/rfc1034.html), [RFC 9110 HTTP Semantics](https://www.rfc-editor.org/rfc/rfc9110.html), [RFC 8446 TLS 1.3](https://www.rfc-editor.org/rfc/rfc8446.html). 기술 문제는 해당 표준을 확인해 검수한다.
