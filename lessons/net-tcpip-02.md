# NET-TCPIP-02 — TCP 연결 설정

예상15~20분 블록: 앞 블록 피드백·개념·흐름시범·기초 문제와 해설. 실제시간 미확인. 전산과 보안 공통강의지만 이번문제는 전산성적만 집계한다.

전제: 클라이언트가 먼저 요청하고 서버가 응답하는 기본상황이며 동시open·재전송 등은 후속학습이다. 연결은 양쪽 TCP가 통신상태와 초기순서번호 등 정보를 맞춰 관리하는 것이다. 상대사용자의 신원인증이나 암호화설정과 다르다.

SYN(synchronize)은 순서번호 동기화, ACK(acknowledgment)는 확인응답을 나타내는 TCP헤더 제어비트다. 입문에서는 SYN은 연결시작정보, ACK는 상대정보확인으로 읽는다. SYN/ACK라는 표기는 별도프로토콜명이 아니라 SYN과ACK비트를 함께 설정했다는 뜻이다. 순서번호는 바이트흐름의 위치를 구분하는 번호이며 자세한계산은 다음에배운다.

기본흐름시범: 클라이언트→서버 SYN / 서버→클라이언트 SYN+ACK / 클라이언트→서버 ACK. 서버의두번째메시지는 상대SYN확인과자기SYN전달을 함께한다. 마지막ACK는 서버의SYN을 클라이언트가 확인하는역할이다. 세메시지에 양쪽시작정보와각각의확인이 담긴다. 오래된중복연결시작정보를 새연결로 혼동하는일을 줄이는 목적도 있다. 이과정자체가 사용자신원확인이나내용암호화를 뜻하지 않는다.

기초문제 CS-NET-002-Q001은 한개만제시하고답변대기. 강사용JSON에 정답·해설·함정·권장시간·검수기록보관. 기준난이도유지이며2문항정답만으로자동상향하지않음.

공식근거: RFC9293 §3.5 Figure6, https://www.rfc-editor.org/rfc/rfc9293.html#section-3.5 (2026-10-26확인). 기술사실은수동대조, 코드검증은구조및기록된판정의일치검사이다.


## 보완 설명 — 각자의 시작 정보를 상대가 확인

클라이언트 SYN: “내 시작 정보야.”

서버 SYN+ACK: “내 시작 정보야(SYN). 네 시작 정보도 받았어(ACK).”

클라이언트 ACK: “네 시작 정보도 받았어.”

각 ACK의 대상은 상대의 SYN이다. ACK 자체를 다시 ACK하는 과정으로 외우지 않는다. CS-NET-002-Q003은 서버 SYN의 확인 대상을 묻는 별도 기초 문제이며 정답은 강사용 파일에만 보관한다.


## 질문 보완 — 서버가 보내는 FCM 알림과 첫 SYN

사용자 질문: 첫 메시지는 클라이언트만 보내는가? 요청 없이 서버가 보낼 수 있는가? FCM은 서버에서 클라이언트로 보내는 것 아닌가?

기본 예시에서는 클라이언트가 먼저 SYN을 보낸다. 모든 프로그램이 영구적으로 클라이언트/서버 한 역할만 갖는 것은 아니다. 서비스 서버도 다른 서버에 연결하면 그 연결을 시작하는 클라이언트가 될 수 있다. TCP는 동시 연결 시작도 지원하지만 이번 기본 문제에서는 제외했다.

TCP 연결 설정과 연결 후 응용 메시지를 구분한다. 연결된 TCP는 양방향으로 데이터를 보낼 수 있다. 업무상 클라이언트가 매번 요청해야만 서버가 데이터를 보낼 수 있다는 제약은 TCP의 규칙이 아니다. HTTP등 응용 프로토콜의 세부 규칙은 별도다.

FCM의 서버발 알림이라는 관찰은 맞다. 논리 흐름은 우리서비스서버→FCM백엔드→플랫폼전달계층→단말앱이다. 우리서비스서버가 단말에 매번 새TCP연결을 거는 것과 동일시하지 않는다. Android 공식문서는FCM의클라우드공유지속연결과TCP/IP활용을설명한다. Apple은APNs, 웹은WebPush등플랫폼별경로가달라모든플랫폼을동일한TCP연결한개로묘사하지않는다. 시작시점을누가정하느냐는TCP첫SYN과업무알림을구분해야한다.

정정 피드백: 서버SYN을 확인하는 것은 클라이언트의 마지막ACK이다. SYN+ACK를 두 덩어리로 나누면 자기SYN+상대SYN확인이다.

## 2026-10-27 보완 — SYN과 포트 개방 구분

서버 SYN은 클라이언트에 새 포트를 열거나 별도 서버를 띄우라는 요청이 아니다. SYN은 초기 순서 번호를 동기화하는 제어 비트다. ACK는 확인 번호 필드가 유효함을 표시하며 이번 서버 ACK는 클라이언트 SYN에 대한 확인이다.

가정 예시: 클라이언트는 포트55000, 서버는8080을 사용한다. 첫 SYN은클라이언트55000→서버8080, SYN+ACK는서버8080→클라이언트55000, 마지막ACK는클라이언트55000→서버8080이다. 클라이언트의포트는첫SYN때이미정해져있다. 같은연결의응답이며새로운수신서버개설/방화벽규칙개방과구분한다.

기억문장: 서버SYN+ACK는 ‘네 시작 번호를 확인했어. 내 시작 번호도 알려줄게.’이다. 초기순서번호는바이트흐름의위치를맞추기위한출발번호이며포트번호와역할이다르다.
