# 통합 패키지: NCS Day 11–12 + TCP/UDP

기준일 2026-10-27. 예상 80–95분(실측 아님). 오늘 도래 복습0건; 다음 10/28 복습4건, 10/30 복습2건.

## 이론 목차

### NCS Day 11 — 추론의 범위와 과잉 일반화
1. 명시 정보와 추론
   1.1 지문에 직접 적힌 사실
   1.2 여러 사실에서 논리적으로 뒷받침되는 결론
2. 안전한 추론
   2.1 지문 범위 안에서만 결론 내리기
   2.2 일부 사례를 전체로 확대하지 않기
   2.3 상관관계를 원인으로 단정하지 않기

시범: “설문 응답자 20명 중 15명이 시스템을 사용하기 편하다고 답했다”로는 응답자 다수가 편하다고 평가했다는 결론을 낼 수 있다. 모든 직원이 편하다고 생각한다거나 시스템이 업무 시간을 줄였다고는 단정할 수 없다.

### NCS Day 12 — 문장 순서와 빈칸의 연결
1. 문장 사이 연결 단서
   1.1 지시어(이러한, 그 결과, 이 방법)
   1.2 접속어(그러나, 따라서, 예를 들어)
2. 배열 순서
   2.1 처음 소개되는 대상·문제 찾기
   2.2 앞 문장을 받아 설명하는 문장 연결
   2.3 결과·요약 문장 위치 확인
3. 빈칸 판단
   3.1 앞뒤 문장의 논리 관계 확인
   3.2 빈칸을 넣고 대명사·접속어가 자연스럽게 이어지는지 검토

시범: “입력 항목이 많아 누락이 발생했다. ___ 시스템은 필수 항목을 먼저 표시하도록 바꿨다.” 빈칸에는 문제의 결과로 개선 조치를 잇는 표현이 와야 한다. 앞뒤 흐름과 접속어를 함께 확인한다.

### 전산 전공 + 정보보안기사 필기 공통 — TCP와 UDP 비교
1. 공통점
   1.1 둘 다 전송 계층 프로토콜이며 포트를 사용
2. TCP
   2.1 연결을 설정하고 바이트 스트림을 전달
   2.2 순서·재전송·확인 등 신뢰성 있는 전달 기능
3. UDP
   3.1 데이터그램 방식
   3.2 전달·중복 방지가 보장되지 않음
   3.3 적은 프로토콜 메커니즘을 제공
4. 선택 원칙
   4.1 순서와 신뢰성 요구가 중요하면 TCP 특성 검토
   4.2 응용이 직접 처리하거나 단순한 메시지 전달을 원하면 UDP 특성 검토
   4.3 UDP도 응용 계층에서 별도 신뢰성·보안을 구현할 수 있음

표준 근거: IETF RFC 9293(TCP) https://www.rfc-editor.org/rfc/rfc9293.html, RFC 768(UDP) https://www.rfc-editor.org/rfc/rfc768.html. RFC 768은 UDP에서 전달·중복 보호가 보장되지 않으며 순서 있는 신뢰성 스트림이 필요하면 TCP를 사용하도록 설명한다.
